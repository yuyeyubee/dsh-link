# FAQ 与排障

## 为什么不直接用 DSH 自带的 LiveShare？

LiveShare 面向「把会话分享给同事」，需要单独的 OAuth/数据库服务，且不解决 Android
原生控制与「手机录音、电脑识别、结果回手机」的链路。DSH Link 是自用、单 token、
多设备直连的方案，依赖更少。

## 为什么需要一台服务器？

两台电脑通常在 NAT 后面，没有公网 IP；手机在移动网络。relay 只做「在线名录 +
WebSocket 转发」，一个 1C1G 小机器足够。电脑/手机都主动外连，不需要端口映射。

## relay 会保存我的会话内容吗？

不会。relay 只在内存里维护在线设备和正在转发中的请求；日志只记录连接、设备、
方法名、耗时，不记录 params/result。会话数据始终在电脑本地。

## token/配对码泄露了怎么办？

配对码等同于密码。立即轮换 token（见 [install.md](install.md) 第 3 节），然后
在所有电脑和手机上重新粘贴新配对码；旧 token 立即失效。

## 远程会话为什么出现在左侧工作区？

插件会把远程会话镜像成本机会话，放在 `[远程] 设备名` 工作区里。点文件夹图标展开，
会话行带「远程」标签；点开就是 DSH 原生对话。这是镜像，不是把远程 DSH 的界面嵌进来。

## 为什么远程会话行只有最近一部分？

每台电脑同步最近 10 个非子代理会话，避免几十个 Agent 同时占用内存。远程新会话会在约
60 秒内出现；打开已有镜像会立即补拉最新记录。

## 原生输入框发送后，本机模型会回答吗？

不会。插件在 `agent/pre-step` 拦下本机模型请求，把 prompt 转发到远程电脑；远程回复通过
实时订阅追加到当前会话。本地这一轮会以结束/blocked 收尾，这是预期行为。

## 为什么会话里会出现「已完成，用时 1 秒」分隔？

镜像把远程的 turn/step 边界也写成了本机事件；每次工具调用/助手回复是一个 step，所以会
出现 DSH 原生的完成分隔。远程内容本身仍完整显示。

## 为什么手机上只能看到「在线」的电脑？

relay 不做离线队列，远程调用必须直达目标电脑。目标电脑关机/DSH 未启动时不会出现
在在线列表里；等它上线后列表会自动刷新。

## 更新插件后远程电脑离线/插件仍显示旧版本怎么办？

代码更新后 DSH 会尝试热重载插件；重载瞬间 relay 连接会断开，通常几秒内自动恢复。
如果一直离线，或 `plugin_manager` 报 `HMR transactions cannot be nested`，说明热重载事务
没有结束，运行中的进程仍是旧模块。此时在**那台电脑**上重启 DeepSeek Harness 即可
（磁盘上的代码已是新版，重启后加载的就是最新版本）。也可以在「设置 → 插件」页面把
dsh-link 关闭再打开一次，这条路不经过 Agent 的工具调用。不要在热重载进行中反复调用
`plugin_manager`，会一直命中同一个事务错误。

## 远程工作区里为什么有些消息显示为工具调用/结果？

DSH 会话日志里包含模型消息、工具调用、工具结果、轮次事件等。DSH Link 把它们压缩成
7 种记录：user / assistant / tool-call / tool-result / turn-start / turn-end / error。
工具参数与结果有长度上限，完整内容请到目标电脑查看。

## 为什么远程会话标题有时是空的？

标题来自 DSH 的 session title projection；极少数会话没有标题（例如刚创建、还没生成）。
插件会回退读取日志里的 `session/title` 事件；都为空时 UI 显示「未命名会话」。

## 手机语音为什么必须用目标电脑识别？

这是设计目标：识别模型与算力留在电脑，手机只上传音频；结果回到手机后可修改再发送。
这样不需要在手机上装模型，也不会把音频发给第三方。

## 语音识别返回空文本 / 识别错字？

- 确认目标电脑 DSH 的语音 provider 已准备（设置 → 语音输入）；
- 录音至少 0.5 秒，环境安静，离麦克风近；
- 首次识别要加载模型，等待时间较长是正常的；
- SenseVoice 对专有名词（如 DSH Link）可能识别成近音词，回填后手动改即可。

## Android 上长连接会断吗？

部分华为/小米 ROM 会在后台清理网络。请在系统「应用启动管理」中允许 DSH Link 后台
活动，并关闭省电限制。App 内置指数退避重连；重新打开后会自动恢复。

## 折叠屏展开后没有变成双栏？

- 确认系统没有强制「应用分屏/兼容模式」；
- App 以窗口宽度 720dp 为阈值；部分 ROM 折叠后窗口宽度上报有延迟，旋转一次可刷新；
- 铰链区域通过 `WindowInfoTracker` 读取，若设备不上报 FoldingFeature，则退化为普通
  宽屏双栏（不会遮挡内容）。

## 插件安装后左侧没有「跨设备」？

1. 确认插件管理里 `@local/dsh-link` 已启用且没有错误；
2. 刷新 DSH 页面；桌面版可重启 DSH；
3. 检查安装目录是否仍是 `link:` 指向的有效路径（移动/删除仓库会使插件失效）；
4. 查看 DSH 日志里是否有 `dsh-link` 相关报错。

## 插件显示「已连接」但看不到另一台电脑？

- 另一台电脑是否也粘贴了**同一个**配对码；
- 两台电脑是否连到同一个 relay URL（配对码里的 `u`）；
- 在另一台电脑执行 `link_status`，确认它的 connection 是 connected；
- relay 日志里看两台 host 是否都 hello 成功。

## 远程发送消息失败？

- 目标电脑该会话是否仍在运行且可写；
- 目标 DSH 是否处于只读/权限限制状态（远程 prompt 走 DSH 自己的 sessionController，
  权限与本地输入一致）；
- 查看 UI 顶部错误条/手机提示，或 `link_debug` 查看会话状态。

## 我能在多台电脑上同时打开同一个远程会话吗？

可以查看，但写入会按 DSH 的会话写入规则串行化；建议同一时间只从一台设备发送，避免
排队/steering 语义混乱。

## 支持 iOS / Web 端吗？

当前只提供 Android App。Web 端可直接用电脑上的 DSH Link 面板控制其他电脑；没有
iOS 客户端计划。

## 端口/证书

- relay 默认 8443；443 可留给其它服务；
- 证书用 Let's Encrypt + sslip.io（`<IP>.sslip.io`），certbot timer 自动续期，
  续期后 deploy hook 重启 relay；
- 如用自有域名，把配对码里的 `u` 换成 `wss://your.domain:8443` 即可（证书需匹配）。

## 如何彻底卸载？

1. 在 DSH 插件管理中移除 `@local/dsh-link`（或删除 profile 里的 bundle 记录）；
2. 删除 `~/.dsh/dsh-link/`（配置与本地配对码副本）；
3. DSH 凭据存储中删除 `dsh-link/token`；
4. 服务器上 `systemctl disable --now dsh-link-relay`，删除 `/opt/dsh-link`；
5. 手机卸载 App。
